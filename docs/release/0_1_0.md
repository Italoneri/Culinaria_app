## Resumo executivo

Release inicial do Saveur — app mobile web de receitas culinárias. Cobre as 4 telas do design handoff (Home, Detalhes, Adicionar, Perfil) + tela de Configurações projetada do zero pelo product-owner. Stack definida, backend implementado, frontend adaptado diretamente dos JSX do Claude Design, PWA configurado para Android Chrome.

### Backend (`apps/api/`)

Implementado em Hono + Bun. Endpoints entregues:

| Endpoint | Descrição |
|----------|-----------|
| `POST /api/auth/*` | Supabase Auth — magic link + Google OAuth |
| `GET /api/recipes` | Listagem com filtros search/category/limit + paginação |
| `POST /api/recipes` | Criar receita (validação completa de campos, enums, valores mínimos) |
| `GET /api/recipes/:id` | Detalhe com 404 explícito |
| `PUT /api/recipes/:id` | Atualização parcial |
| `DELETE /api/recipes/:id` | Deleção idempotente |
| `POST/DELETE /api/recipes/:id/favorites` | Favoritar/desfavoritar (upsert idempotente) |
| `GET /api/favorites` | Listagem de favoritos com paginação |
| `GET /api/categories` | 5 categorias com contagem de receitas públicas |
| `GET/PUT /api/profile` | Perfil + stats calculados (fallback 0 quando null) |
| `GET/POST /api/profile/collections` | Coleções com validações |
| `POST /api/upload/presign` | Presigned URL para recipe/avatar no Supabase Storage |
| `GET /api/health` | Health check sem autenticação |

Arquivos adicionais:
- `supabase/migrations/20260524000001_initial_schema.sql` — schema completo com RLS e trigger `auto-profile`
- `supabase/seed.sql` — 6 receitas seed baseadas no `data.js` do handoff
- `packages/types/src/index.ts` — tipos compartilhados (Recipe, Profile, Collection, etc.)

**Campo `notes`** incluído na tabela `recipes` (identificado pelo backend-dev na análise do AddScreen — não existia no data.js original).

### Frontend (`apps/web/`)

Implementado em Next.js 14 App Router. JSX do handoff adaptados sem reescrita total.

**Componentes (`src/components/ui/`):**
- `icons.tsx` — 19 ícones SVG tipados
- `bottom-nav.tsx` — 5 itens, botão `+` centralizado âmbar 52×52, `aria-label` e `role="navigation"`
- `recipe-card.tsx` — FeaturedCard, RecipeCard, MiniCard com `data-testid` completos
- `pill.tsx` — Pill badge para stats de receita

**Telas:**
- `/` — HomeScreen com chips de categoria interativos, FeaturedCard, seções "Salvas recentemente" e "Para hoje à noite", empty state
- `/receita/[id]` — DetailScreen com tabs ingredientes/passos, checklist interativo, dica do chef, CTA fixo
- `/adicionar` — AddScreen com campos dinâmicos de ingredientes/passos, steppers, validação com mensagens de erro, área de upload de foto
- `/perfil` — ProfileScreen com modo de edição inline, grid de favoritas 2 colunas, coleções, avatar com câmera, premium badge

**PWA Android:**
- `public/manifest.json` — `theme_color: #E8A020`, `display: standalone`, `orientation: portrait`, `start_url: /`
- `public/sw.js` — cache-first (assets estáticos), network-first (páginas), stale-while-revalidate (imagens)
- `viewport-fit=cover` + `overscroll-behavior: none`

**Dados:** mock local baseado em `data.js` do handoff. Integração com API pronta para ativação via `api-contract.md`.
